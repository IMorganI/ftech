# Админка: доступ и API

## Первый вход

```bash
npm run admin:create -- you@company.com admin     # печатает временный пароль один раз
```

1. `POST /admin/v1/auth/login` `{ email, password }` → `{ next: "totp_setup", totpSecret, otpauthUrl }`.
   Добавь секрет в Google Authenticator / 1Password / Authy (или QR из `otpauthUrl`).
2. `POST /admin/v1/auth/totp` `{ code }` — 6 цифр из приложения → `{ next: "change_password" }`.
3. `POST /admin/v1/me/password` `{ currentPassword, newPassword }` — минимум 12 символов, буквы и цифры.

Дальше каждый вход: пароль → код из приложения. Публичной регистрации нет.

## Защита

| Что | Как |
|---|---|
| Пароли | scrypt с солью, временный пароль обязательно меняется при первом входе |
| 2FA | Обязательна для всех (TOTP, RFC 6238); один код нельзя использовать дважды |
| Перебор | 10 попыток входа в минуту с IP; 5 неверных паролей или кодов — блокировка на 15 минут |
| Сессия | Случайный токен в HttpOnly-cookie (`SameSite=Strict`, `Secure` по HTTPS), в базе только хэш; новый токен после 2FA; 12 ч максимум, 30 мин бездействия |
| CSRF | Изменяющие запросы принимаются только с `Content-Type: application/json` |
| Утечки | Ключи сайтов и секреты показываются один раз, в списки и журнал не попадают |
| Аудит | Каждое изменение и вход — в `audit_log` с «до/после», записи нельзя изменить или удалить |

Смена пароля закрывает остальные сессии пользователя; блокировка, смена роли или сброс 2FA — все его сессии.

## Заработок

У каждого оператора задаётся **комиссия платформы** (`platform_fee_bps`, 150 = 1.5%) — процент
с каждого успешного депозита. В момент успеха в платеже сохраняется снимок: `platform_fee`
(заработок) и `provider_fee` (расход на провайдера, по комиссии аккаунта). Поэтому смена процента
не переписывает уже заработанное. Округление — вниз до цента.

## История платежа и зависшие деньги

**Платежи → нажать на платёж** — карточка: где сейчас деньги (зачислен, ждёт оплаты, отправка не подтверждена,
оплачен но не зачислен…), **что дальше** (что сделает система сама, что нужно от сотрудника, что может сайт)
и **история** по порядку: запрос сайта → выбор аккаунта и почему → ответ провайдера на создание → вебхуки провайдера →
подтверждение оплаты → проводки (сходятся ли) → части выплаты, одобрение и исполнение с именами сотрудников →
уведомления сайту → проблемы.

**Контроль → Зависшие деньги** — где и сколько денег ждёт, как давно и что делать:

| Категория | Важность | Что значит |
|---|---|---|
| Отправка провайдеру не подтверждена | действие | Ответ провайдера потерян; без каскада, пока не выяснится, создан ли платёж |
| Оплачено, но не зачислено | действие | Провайдер не подтвердил сумму/валюту или они не совпали |
| Возврат без ответа провайдера | действие | Неизвестно, ушли ли деньги игроку |
| Открытые проблемы | действие | Расхождения с провайдером |
| Ручные выплаты ждут сотрудника | внимание | Нужно перевести и отметить (крупные — сначала одобрить) |
| Вебхуки провайдера не обработаны | внимание | Фоновая задача повторяет сама |
| Сайт не получил уведомление | внимание | Все попытки доставки исчерпаны |
| Не отправлены провайдеру | внимание | Процесс перезапускался; сверка отправит сама |
| Ждут оплаты игроком > 15 мин | сведения | Обычно игрок ушёл; заказ закроется по сроку |

Плюс сумма лимита, зарезервированного под незавершённые платежи. Счётчик в меню — число платежей, где нужно действие.
В Telegram приходит, если отправка не подтверждена или вебхук провайдера не обработан дольше 10 минут.

API: `GET /admin/v1/transactions/:id/timeline`, `GET /admin/v1/stuck` (viewer).

## Аналитика и выгрузки

Раздел **Деньги → Аналитика**: период (сегодня, 7 и 30 дней или свои даты, не больше 366 дней), разбивка по
операторам, сайтам, аккаунтам или провайдерам, фильтр по оператору.

| Колонка | Как считается |
|---|---|
| Депозиты | успешные / все за период |
| Конверсия | успешные ÷ (успешные + отказы); ждущие оплаты не учитываются |
| Одобрение попыток | успешные попытки ÷ завершённые попытки; при разбивке по аккаунтам — по аккаунту каждой попытки (каскад виден) |
| Оборот, средний чек | по успешным депозитам |
| Заработали / Провайдеру | комиссия платформы и провайдера, зафиксированные в момент успешной оплаты |
| Выплачено | по операторам и сайтам — успешные выплаты; по аккаунтам и провайдерам — возвраты на карты через аккаунт |

Разные валюты не складываются: итог — по каждой валюте.

- `GET /admin/v1/analytics?period=today|7d|30d|custom&from=ГГГГ-ММ-ДД&to=ГГГГ-ММ-ДД&groupBy=operator|site|account|provider&operatorId=&tz=` — JSON (viewer).
- `GET /admin/v1/analytics.csv?…` — та же таблица файлом (viewer).
- `GET /admin/v1/export/transactions.csv?…` — все платежи построчно, до 100 000 строк (operator). Содержит ID игроков,
  поэтому каждая выгрузка пишется в журнал (`export.transactions`: период, оператор, число строк).

CSV — для Excel и Google Таблиц с русской/украинской локалью: UTF-8 с BOM, разделитель `;`, копейки через запятую.
`&decimal=dot` — разделитель `,` и точка. Ячейки, начинающиеся с `= + - @`, экранируются апострофом,
чтобы таблица не выполнила их как формулу (ID игрока приходит от сайта и может быть чем угодно).

## Эндпоинты

Все под `/admin/v1`, суммы — строки в центах.

| Метод | Путь | Роль |
|---|---|---|
| GET | `/overview` — платежи и оборот за 24 ч, ожидающие, расхождения, недоставленные вебхуки | viewer |
| GET | `/stats?period=today\|7d\|30d&tz=Europe/Kyiv` — успешные депозиты, конверсия, оборот, заработок платформы, расходы на провайдеров, график, разбивка по сайтам | viewer |
| GET/POST | `/operators`, PATCH `/operators/:id` | viewer / admin |
| GET/POST | `/sites` (POST отдаёт `apiKey` и `webhookSecret` один раз), PATCH `/sites/:id` | viewer / admin |
| POST | `/sites/:id/rotate-key`, `/sites/:id/rotate-webhook-secret` | admin |
| GET/POST | `/providers` | viewer / admin |
| GET | `/accounts` — с оборотом за сегодня (`used_today`, `reserved_today`) | viewer |
| POST | `/accounts` | admin |
| PATCH | `/accounts/:id` — оперативные поля operator, структурные только admin | operator |
| GET | `/transactions?status=&siteId=&accountId=&player=&before=&limit=` | viewer |
| GET | `/transactions/:id` — попытки с причинами выбора, проводки, вебхуки | viewer |
| GET | `/issues?all=true`, POST `/issues/:id/resolve` `{ note }` | viewer / operator |
| GET/POST | `/users`, PATCH `/users/:id`, POST `/users/:id/reset-2fa` | admin |
| GET | `/audit?entity=&entityId=&beforeId=&limit=` | admin |
