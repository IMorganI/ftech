# Подключение платёжного провайдера

Новый провайдер — это **один файл**: адаптер (как ходить в API провайдера) и его **карточка** (`manifest`).
Борда строит экран подключения по карточке сама: поля ключей, адрес вебхука, шаги в кабинете провайдера,
проверку и статус вебхука. Роутер, лимиты, каскад, выплаты и журнал про конкретных провайдеров ничего не знают.

Образцы: `src/providers/testpay.ts` (подпись вебхуков секретом от провайдера — как у большинства),
`src/providers/viva.ts` (без подписи, защита токеном в адресе).

## Карточка (`ProviderManifest`)

| Поле | Что это |
|---|---|
| `title`, `summary`, `methods` | Название, одна строка о провайдере, способы оплаты для игрока |
| `links.dashboard`, `links.docs` | Ссылки на кабинет и документацию (кнопки в борде) |
| `fields` | Поля ключей: `label`, `help` (где взять в кабинете), `secret`, `required`, `options`, `default`. `stage: 'webhook'` — поле вводится на шаге «Вебхук» (секрет подписи, который провайдер выдаёт после создания вебхука) |
| `capabilities` | Возвраты, частичные возвраты, сверка суммы — показываются в борде |
| `webhook.scheme` | `signature` — провайдер подписывает вебхуки своим секретом; `token` — не подписывает, защищает только токен в адресе; `internal` — тестовый внутри сервера |
| `webhook.events`, `webhook.steps`, `webhook.note` | Какие события отметить, что сделать в кабинете по шагам, что провайдер делает при сохранении адреса |

## Что реализовать в адаптере

| Метод | Что делает |
|---|---|
| `createPayment(creds, req)` | Создаёт платёж. Возвращает ссылку на страницу оплаты провайдера (`redirect`) или явный отказ (`declined`). `req.reference` — наш ID попытки. |
| `getStatus(creds, providerRef)` | Статус у провайдера: `pending`, `success`, `declined`. |
| `verifyWebhook(creds, headers, rawBody, query)` | Проверяет **подпись** и достаёт `eventId`, `providerRef`. Тестовое событие из кабинета — `{ test: true }`. Ошибка — `InvalidWebhookError` с понятной причиной (она попадёт в журнал вебхуков в борде). |
| `checkConnection(creds)` | Проверка ключей без создания платежей: список пунктов «что работает, что нет и почему». |
| `refund`, `paidAmount`, `webhookChallenge` | По возможности: возвраты (выплаты по closed loop), сверка оплаченной суммы, ответ на GET-проверку адреса. |

Токен в адресе вебхука проверяет **ядро** для всех схем, кроме `internal` — в адаптере этого делать не нужно.

## Правила

1. **Никаких номеров карт.** Только страница оплаты / виджет провайдера (иначе — полный аудит PCI DSS).
2. **Статус из тела вебхука не используется.** После проверки подписи ядро само вызывает `getStatus`.
3. **Ошибка сети в `createPayment` — исключение, не отказ**: неизвестно, создался ли платёж; попытку разберёт сверка.
4. **Таймауты** на каждый HTTP-запрос (5–10 с).
5. **Ключи** вводятся в борде и хранятся зашифрованными (`ENCRYPTION_KEY`); адаптер получает их в `creds.secret` (JSON по полям карточки).

## Шаги

1. `src/providers/<имя>.ts` — адаптер с карточкой.
2. `src/index.ts`: `providers.register(new XAdapter(...))`.
3. Тесты: создание, отказ, подпись (верная, чужая, устаревшая), тестовое событие, статус, проверка ключей.

Всё остальное — запись провайдера в базе, адрес вебхука, форма ключей, шаги подключения, журнал вебхуков —
появляется автоматически.

## Как подключение выглядит в борде

Раздел «Операторы и аккаунты» → оператор → «Подключить платёжный аккаунт». Аккаунт создаётся **выключенным**,
адрес вебхука у него есть сразу. Дальше 4 шага:

1. **Ключи** — поля из карточки.
2. **Проверка** — `checkConnection`.
3. **Вебхук** — адрес с кнопкой «Копировать», шаги для кабинета провайдера, поле секрета подписи (если нужен)
   и живой статус: «ждём первый вебхук» → «вебхуки приходят» или «приходит, но отклоняется: <причина>».
   Ниже — журнал последних вебхуков (принят, тест, повтор, отклонён, ошибка) с причинами.
4. **Запуск** — включить в маршрутизацию и провести тестовый платёж.

Если адрес вебхука утёк или указан не туда — «Выпустить новый адрес» (старый перестаёт работать сразу).

## TestPay — учебный провайдер

Есть при `MOCK_PROVIDER_ENABLED=true`. Кабинет: `<PUBLIC_BASE_URL>/testpay` — создать API-ключ, вставить адрес
вебхука, получить секрет `whsec_…`, отправить тестовое событие. Позволяет пройти сценарий «как у настоящих»
без договора с провайдером. Вебхуки доставляет только на этот же сервер.
