# Подключение платёжного провайдера

Каждый провайдер — отдельный адаптер с интерфейсом `ProviderAdapter` (`src/providers/types.ts`).
Роутер, лимиты, каскад, вебхуки и журнал про конкретных провайдеров ничего не знают.

## Что реализовать

| Метод | Что делает |
|---|---|
| `createPayment(creds, req)` | Создаёт платёж у провайдера. Возвращает ссылку на его страницу оплаты (`redirect`) или мгновенный отказ (`declined`). `req.reference` — наш ID попытки, передай его провайдеру как ID заказа. |
| `getStatus(creds, providerRef)` | Статус платежа у провайдера: `pending`, `success`, `declined`. |
| `verifyWebhook(creds, headers, rawBody)` | Проверяет подпись вебхука провайдера (по его документации) и достаёт `eventId` и `providerRef`. Неверная подпись — `InvalidWebhookError`. |

## Правила

1. **Никаких номеров карт.** Только hosted payment page / виджет провайдера. Если провайдер
   предлагает «прямой» API с номером карты — не используем: это полный аудит PCI DSS.
2. **Статус из вебхука не используется.** После проверки подписи система сама вызывает `getStatus`.
   Поэтому `verifyWebhook` достаёт только идентификаторы.
3. **Ошибка сети в `createPayment` — исключение, не отказ.** Мы не знаем, создался ли платёж,
   поэтому попытка остаётся `pending` и её разбирает сверка. `declined` возвращай, только когда
   провайдер явно ответил отказом.
4. **Таймауты.** Каждый HTTP-запрос к провайдеру — с таймаутом (5–10 с).
5. **Секреты** приходят в `creds.secret` из хранилища секретов по `credentials_ref` аккаунта.
   В коде и в базе их нет.

## Шаги

1. `src/providers/<имя>.ts` — класс адаптера (образец — `MockAdapter` в `src/providers/mock.ts`).
2. Зарегистрировать в `src/index.ts`: `providers.register(new XAdapter(...))`.
3. В базе: строка в `providers` с `adapter = '<имя>'`, у мерчант-аккаунтов — `credentials_ref`.
4. Секрет: переменная `PROVIDER_SECRET_<REF>` (в проде — хранилище секретов).
5. В кабинете провайдера указать адрес вебхуков: `<PUBLIC_BASE_URL>/v1/provider-webhooks/<id аккаунта>`.
6. Тесты: создание, отказ, проверка подписи (верная, неверная, старая), статус.
