# API для сайтов

Все запросы — JSON по HTTPS. Суммы — **целые числа в минорных единицах** (центы): `2500` = 25.00 EUR.

## Авторизация

```
Authorization: Bearer ftk_...
```

Ключ выдаётся сайту один раз при создании; у нас хранится только его хэш. Ключ можно отозвать.
Без ключа или с неверным ключом — `401`.

Ограничение частоты: по умолчанию 600 запросов в минуту на ключ, сверх — `429`.

## Создать депозит

```
POST /v1/deposits
Idempotency-Key: order-2026-000123      ← обязательно, 8–128 символов
```

```json
{
  "amount": 2500,
  "currency": "EUR",
  "returnUrl": "https://casino.example/deposit/return",
  "player": {
    "id": "u42",
    "country": "MT",
    "kyc": "verified",
    "depositLimitDaily": 50000,
    "selfExcluded": false
  }
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `amount` | да | Целое > 0, в центах. Можно строкой: `"2500"` |
| `currency` | да | ISO 4217: `EUR`, `BRL`, `CAD`… |
| `returnUrl` | нет | Куда провайдер вернёт игрока после оплаты (только `https://`) |
| `player.id` | да | ID игрока на стороне сайта |
| `player.country` | да | ISO 3166-1: `MT`, `DE`, `BR`… |
| `player.kyc` | нет | `none`, `pending`, `verified`, `rejected`. Не передал — остаётся сохранённый статус |
| `player.depositLimitDaily` | нет | Лимит депозитов игрока за сутки (UTC, в валюте депозита), в центах. **Только снижает** сохранённый лимит |
| `player.selfExcluded` | нет | `true` — включить самоисключение. `false` или отсутствие поля **ничего не снимают** |

**Ограничения игрока хранятся у нас и не перезаписываются депозитом.** Из депозита их можно только
ужесточить: включить самоисключение, снизить лимит, сообщить KYC. Снять самоисключение, повысить или
снять лимит — только через [API ограничений](#ограничения-игрока).

**Ответ** `201` (новый платёж) или `200` (повтор с тем же `Idempotency-Key`):

```json
{
  "id": "e68b2670-321e-4fdb-a9e9-cf5c2c76031c",
  "type": "deposit",
  "status": "pending",
  "amount": "2500",
  "currency": "EUR",
  "declineCode": null,
  "paymentUrl": "https://pay.provider.example/checkout/abc123",
  "createdAt": "2026-11-11T21:48:22.639Z",
  "updatedAt": "2026-11-11T21:48:22.639Z"
}
```

**`paymentUrl`** — страница оплаты провайдера. Отправь туда игрока (редирект): он вводит карту
у провайдера, к нам и к тебе номера карт не попадают. Ссылка есть, пока `status` = `pending`.
Если провайдер отказал и платёж ушёл на другой аккаунт, придёт вебхук `deposit.payment_url_changed`
с новой ссылкой. Если `status` = `pending`, а `paymentUrl` = `null` — провайдер не ответил на создание платежа.
Платёж **не** перекидывается на другой аккаунт вслепую: провайдер мог успеть его создать. Мы ищем его
у провайдера или ждём истечения срока оплаты; итог придёт вебхуком (`deposit.succeeded` /
`deposit.declined` с `provider_unavailable`).

Отказ — это тоже успешно созданный платёж (`201`) со `status: "declined"` и причиной в `declineCode`:

| `declineCode` | Что значит |
|---|---|
| `player_self_excluded` | Игрок в самоисключении |
| `country_not_licensed` | Страна игрока не входит в лицензии оператора |
| `kyc_rejected` | KYC игрока отклонён |
| `kyc_required` | Сумма выше порога оператора, а KYC не подтверждён |
| `player_limit_exceeded` | Превышен дневной лимит игрока |
| `no_route` | Нет мерчант-аккаунта, который принимает этот платёж сейчас |
| `all_attempts_failed` | Провайдеры отклонили платёж на всех попытках |
| `provider_unavailable` | Провайдер не ответил на создание платежа, а срок оплаты такого заказа истёк. Платёж не перекидывался на другой аккаунт, чтобы игрок не заплатил дважды. Можно создать новый депозит |

**Повторы.** Повторяй запрос с тем же `Idempotency-Key` сколько угодно — второй платёж не создастся.
Тот же ключ с другими параметрами — `409 idempotency_conflict`.

## Ограничения игрока

Ответственная игра: самоисключение, дневной лимит депозитов, KYC. `{id}` — ID игрока на стороне сайта
(игрок появляется после первого депозита).

```
GET /v1/players/{id}/restrictions
```

```json
{
  "playerId": "u42", "selfExcluded": false, "selfExcludedAt": null, "kyc": "verified",
  "depositLimitDaily": "20000",
  "pendingDepositLimit": { "value": "50000", "effectiveAt": "2026-11-13T12:00:00.000Z" },
  "version": 7
}
```

```
PUT /v1/players/{id}/restrictions
```

```json
{ "version": 7, "selfExcluded": false, "depositLimitDaily": 50000, "kyc": "verified", "note": "запрос игрока в личном кабинете" }
```

Все поля необязательны.

| Поле | Правило |
|---|---|
| `selfExcluded` | `true` — сразу. `false` — снять самоисключение (только здесь) |
| `depositLimitDaily` | Снижение — сразу. Повышение или снятие (`null`) — через период охлаждения оператора (по умолчанию 24 ч), до этого действует прежний лимит; видно в `pendingDepositLimit`. Новое снижение отменяет ожидающее повышение |
| `kyc` | Новый статус KYC |
| `version` | Необязательно. Если передан и не совпадает с текущим — `409 version_conflict` (кто-то уже поменял ограничения) |
| `note` | Комментарий — попадает в журнал изменений игрока |

Каждое изменение (откуда: депозит, выплата, API, система) записывается в журнал, который нельзя изменить.

## Статус депозита

```
GET /v1/deposits/{id}
```

Отдаёт тот же объект. Сайт видит только свои платежи; чужой или несуществующий — `404`.

## Выплата игроку

```
POST /v1/payouts
Idempotency-Key: payout-req-2026-000077
```

```json
{ "amount": 8000, "currency": "EUR", "withdrawalId": "W-000077", "player": { "id": "u42", "kyc": "verified" } }
```

Перед вызовом сайт сам проверяет, что игроку можно выводить (баланс, отыгрыш бонусов, свои правила).
Мы выплачиваем по принципу **closed loop**:

1. Сначала **возвраты на карты**, с которых игрок вносил депозиты в этой валюте (от последних к ранним),
   каждый — не больше ещё не возвращённой части депозита.
2. Что не покрывается возвратами (выигрыш сверх депозитов), — **ручная выплата**: оператор переводит
   сам и отмечает в борде.

| Поле | Обязательно | Описание |
|---|---|---|
| `amount` | да | Сумма в центах |
| `currency` | да | ISO 4217 |
| `withdrawalId` | да | ID вывода в твоей системе. **Один вывод — одна выплата**: повтор с тем же `withdrawalId`, но другим `Idempotency-Key` — `409 duplicate_withdrawal` (в `details.payoutId` — уже созданная выплата) |
| `player.id` | да | ID игрока на стороне сайта. Должен был делать депозиты через нас, иначе `422 unknown_player` |
| `player.kyc` | нет | Обновить статус KYC. По умолчанию выплаты требуют `verified` |

**Ответ** `201` / `200` (повтор):

```json
{
  "id": "4f1c…", "type": "payout", "status": "pending", "amount": "8000", "currency": "EUR",
  "declineCode": null, "refundAmount": "5000", "manualAmount": "3000",
  "parts": [
    { "kind": "refund", "amount": "3000", "status": "success" },
    { "kind": "refund", "amount": "2000", "status": "success" },
    { "kind": "manual", "amount": "3000", "status": "pending" }
  ]
}
```

| `status` | Что значит |
|---|---|
| `success` | Все части выполнены — деньги у игрока |
| `pending` | Есть ручная часть, которую ждём от оператора (или возврат в обработке) |
| `declined` | Отказ: `declineCode` = `kyc_required` или `amount_over_limit` (больше максимальной выплаты оператора) |

Баланс игрока ведёт казино: спиши (зарезервируй) сумму у себя **до** вызова и верни её игроку, если выплата
отклонена. Крупные ручные выплаты оператор может настроить на одобрение вторым сотрудником.

Статус выплаты — `GET /v1/payouts/{id}`. Если провайдер отказал в возврате, эта часть автоматически
становится ручной. Если провайдер не ответил, возврат не повторяется автоматически (чтобы не вернуть дважды),
а попадает оператору на проверку.

## Вебхуки сайту

Когда статус платежа меняется, мы отправляем `POST` на адрес вебхука сайта:

```json
{
  "id": "evt_1842",
  "event": "deposit.succeeded",
  "data": { "id": "c9bd…", "type": "deposit", "status": "success", "amount": "2500", "currency": "EUR",
            "declineCode": null, "paymentUrl": null, "updatedAt": "2026-11-11T21:58:18.351Z" }
}
```

| `event` | Когда |
|---|---|
| `deposit.succeeded` | Провайдер подтвердил оплату — можно зачислять игроку |
| `deposit.declined` | Платёж окончательно отклонён |
| `deposit.payment_url_changed` | После каскада у платежа новая страница оплаты (`data.paymentUrl`) |
| `payout.succeeded` | Выплата полностью выполнена |
| `payout.requires_manual` | Возвраты на карты выполнены, осталась ручная часть — ждём оператора |

**Ответь `2xx` в течение 10 секунд.** Иначе повторим с растущей паузой (10 с, 20 с, 40 с… до 6 ч),
всего до 12 попыток. Одно событие может прийти дважды — обрабатывай идемпотентно по `id` события.

**Обязательно проверяй подпись.** Заголовок `Ftech-Signature: t=<unix-время>,v1=<подпись>`,
где подпись — HMAC-SHA256 от строки `t + "." + тело запроса` секретом вебхука сайта:

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

function verify(rawBody, header, secret) {
  const { t, v1 } = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false;        // не старше 5 минут
  const expected = createHmac('sha256', secret).update(`${t}.${rawBody}`).digest();
  const got = Buffer.from(v1, 'hex');
  return got.length === expected.length && timingSafeEqual(got, expected);
}
```

Подпись считай от **сырого тела**, до разбора JSON. Не зачисляй деньги по вебхуку без проверки подписи.

## Ошибки

```json
{ "error": { "code": "invalid_request", "message": "...", "details": [...] } }
```

`400` — ошибка в запросе, `401` — авторизация, `404` — не найдено, `409` — конфликт (`idempotency_conflict`,
`duplicate_withdrawal`, `version_conflict`),
`429` — слишком часто, `500` — внутренняя ошибка (подробности только в наших логах).
