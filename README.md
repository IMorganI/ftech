# ftech — платёжный оркестратор

Единая точка входа для лицензированных гемблинг-продуктов: сайты подключаются по одному API,
а роутер распределяет платежи между мерчант-аккаунтами платёжных провайдеров по лимитам,
валютам, странам и комиссиям.

## Посмотреть вживую (GitHub Codespaces)

[![Открыть в GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/IMorganI/ftech)

1. Нажми кнопку выше → **Create codespace**. Первый запуск — 3–5 минут: поднимаются сервер
   и база, применяются миграции, создаются демо-данные и первый админ.
2. Откроется файл **DEMO-CREDENTIALS.md** с адресом борды, временным паролем
   и API-ключом демо-сайта.
3. Открой борду (вкладка **Ports** → порт 3000 → значок глобуса, в конце адреса `/admin`).
   При первом входе отсканируй QR-код в Google Authenticator / 1Password / Authy и смени пароль.
4. Во вкладке **Песочница** вставь API-ключ, создай депозит, нажми «Открыть страницу оплаты» →
   «Оплатить» — и смотри, как платёж появляется в «Платежах» и на шкале аккаунта.

### Каждый следующий запуск

Открой Codespace и в терминале выполни **одну команду**:

```bash
npm run up
```

Она обновит код, перезапустит сервер в фоне, дождётся, пока он ответит, и напечатает адрес борды.
Дальше: вкладка **Ports** → порт 3000 → правый клик → **Видимость порта → Public**.
Адрес без `/admin` тоже работает — корень сайта ведёт в борду.

| Видишь | Что делать |
|---|---|
| HTTP ERROR 401 | Порт приватный → сделай Public |
| HTTP ERROR 502 | Сервер не запущен → `npm run up` |
| HTTP ERROR 404 с пустой страницей | Туннель GitHub «потерял» Codespace (бывает после перезапуска) → создай новый Codespace |
| Старая версия борды | `npm run up`, затем Cmd+Shift+R |

Codespace засыпает через 30 минут без активности, данные сохраняются; бесплатно — 120 часов в месяц.
Адрес по умолчанию приватный: открыть его можешь только ты (вход через GitHub).

## Уведомления в Telegram

Бот пишет, когда нужно вмешаться: новая проблема с платежом, сайт не получил уведомление,
аккаунт дошёл до порога лимита, провайдер не отвечает. Каждое событие — один раз.

1. В Telegram: **@BotFather** → `/newbot` → получишь токен. Напиши своему боту любое сообщение.
2. В Codespace: `echo 'TELEGRAM_BOT_TOKEN=<токен>' >> .env` (токен — только сюда, не в чат и не в git).
3. `set -a; . ./.env; set +a; npm run telegram:setup` — найдёт твой чат и запишет `TELEGRAM_CHAT_ID`; бот пришлёт «ftech подключён».
4. `npm run up`.

## Принципы

- **Лимит игрока ≠ лимит аккаунта.** Если превышен лимит игрока (ответственная игра, KYC,
  самоисключение) — платёж отклоняется. Перекидывать на другой аккаунт можно только когда
  заполнен дневной/месячный оборот мерчант-аккаунта.
- **Ограничения игрока хранятся у нас.** Самоисключение «залипает», лимит из депозита можно только снизить,
  повышение — через API и период охлаждения. Каждое изменение — в неизменяемом журнале.
- **Неизвестность — не отказ.** Если ответ провайдера потерян, платёж не перекидывается на другой аккаунт,
  пока не подтверждено, что первого нет (или пока не истёк срок его оплаты): игрок не заплатит дважды.
- **Зачисляем только подтверждённое:** статус, сумма и валюта фактической оплаты от провайдера.
- **Один вывод казино — одна выплата** (`withdrawalId`); крупные ручные выплаты — два сотрудника.
- **Каждая операция — в журнале (ledger)** с привязкой к игроку, оператору, провайдеру и аккаунту.
- **Идемпотентность:** повторный запрос с тем же ключом не создаёт второй платёж.
- **Секреты не хранятся в репозитории.** Ключи провайдеров — только в переменных окружения.
- **Изменения — через pull request**, в `main` ничего не попадает без ревью.

## Защита кода

- `main` защищён: только через pull request с зелёным CI и одобрением владельца (CODEOWNERS).
- Зависимости: точные версии в `package-lock.json`, установочные скрипты пакетов запрещены (`.npmrc`),
  `npm audit` в CI, еженедельные обновления от Dependabot.
- GitHub Actions закреплены по хэшу коммита, у CI права только на чтение.
- Код проприетарный, см. `LICENSE`.

## Запуск локально

Нужны Node.js 20+ и Docker.

```bash
cp .env.example .env
docker compose up -d          # PostgreSQL
npm install
npm run migrate               # создать таблицы
npm run seed                  # демо-оператор, сайт и аккаунты; печатает API-ключ и секрет вебхуков
npm run dev                   # сервер на http://localhost:3000
```

Проверка: `GET /health` — процесс жив, `GET /ready` — есть связь с базой.

Пример депозита (ключ из `npm run seed`):

```bash
curl -X POST localhost:3000/v1/deposits \
  -H "Authorization: Bearer ftk_..." -H "Idempotency-Key: demo-0001" \
  -H "Content-Type: application/json" \
  -d '{"amount":2500,"currency":"EUR","player":{"id":"u42","country":"MT","kyc":"verified"}}'
```

В ответе будет `paymentUrl` — открой его в браузере: это страница оплаты мок-провайдера
с кнопками «Оплатить» и «Отклонить». После нажатия статус платежа поменяется, а сайту
уйдёт вебхук (адрес вебхука можно передать в сид: `npm run seed -- https://my-site/hooks`).

Админка: `npm run admin:create -- you@company.com admin` создаёт первого пользователя
(временный пароль, при входе — настройка 2FA и смена пароля).

Документация: [API для сайтов](docs/API.md) · [Подключение провайдера](docs/PROVIDERS.md) · [Viva Wallet](docs/VIVA.md) · [Админка](docs/ADMIN.md).

## Путь платежа

```
Сайт ──POST /v1/deposits──► Роутер: проверки игрока, выбор аккаунта, резерв лимита (коммит)
                              │
                              ▼  запрос к провайдеру — ВНЕ транзакции базы
                         Провайдер ──► paymentUrl ──► игрок платит на странице провайдера
                              │
                              ▼  вебхук провайдера: проверка подписи + перепроверка статуса у провайдера
                         Успех: резерв → оборот, проводки, событие в очередь (outbox)
                         Отказ: резерв снят, каскад на следующий аккаунт, новая ссылка
                              │
                              ▼  воркер: подписанный вебхук сайту, повторы с паузой
                            Сайт
```

Фоновые задачи (в том же процессе, `WORKERS_ENABLED=true`): доставка вебхуков сайтам каждую
секунду и сверка ожидающих платежей каждые 20 секунд — если через `RECONCILE_AFTER_SEC`
(по умолчанию 60 с) от провайдера не пришёл вебхук, система сама спросит статус.
Если провайдер сообщает оплаченную сумму и она не совпала с нашей, платёж не зачисляется
и попадает в «Проблемы» (`amount_mismatch`). Расхождения, которые нельзя решить автоматически (например,
провайдер подтвердил оплату по уже закрытой попытке), пишутся в `reconciliation_issues`.

## Как роутер выбирает аккаунт

1. **Проверки игрока** — самоисключение, лицензия страны, KYC, дневной лимит игрока.
   Не прошёл — отказ. Лимит игрока никогда не обходится через другой аккаунт.
2. **Отбор аккаунтов** оператора по валюте, стране, мин/макс сумме.
3. **Лимиты аккаунтов**: строки оборота блокируются в базе, свободный лимит считается
   до порога переключения (95% дневного и месячного).
4. **Выбор**: аккаунт, где игрок уже платил → приоритет → комиссия → больше свободного места.
5. **Резерв** суммы. При успехе у провайдера резерв становится оборотом и пишутся проводки,
   при отказе резерв снимается и платёж уходит на следующий аккаунт (до `max_attempts`).

Тесты: `npm test`. Тесты базы запускаются, если задан `TEST_DATABASE_URL`
(в GitHub Actions задаётся автоматически).

## Модель данных

- **operators** — владелец лицензии; **sites** — его сайты, которые ходят в API (храним только хэш ключа).
- **providers** — тип интеграции; **merchant_accounts** — конкретные аккаунты с валютами, странами,
  мин/макс суммой, дневным/месячным лимитом, порогом переключения (95%) и комиссией.
- **account_usage** — оборот аккаунта по дням; строка блокируется при резервировании лимита.
- **players** — игрок сайта: страна, KYC, свой лимит депозитов, самоисключение, «липкий» аккаунт.
- **transactions** / **transaction_attempts** — платёж и каждая попытка через конкретный аккаунт (каскад).
- **ledger_entries** — журнал проводок, только добавление (изменение и удаление запрещены на уровне базы).

Суммы — `BIGINT` в минорных единицах (центы), никаких дробных чисел для денег.
