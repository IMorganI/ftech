# ftech — платёжный оркестратор

Единая точка входа для лицензированных гемблинг-продуктов: сайты подключаются по одному API,
а роутер распределяет платежи между мерчант-аккаунтами платёжных провайдеров по лимитам,
валютам, странам и комиссиям.

## Принципы

- **Лимит игрока ≠ лимит аккаунта.** Если превышен лимит игрока (ответственная игра, KYC,
  самоисключение) — платёж отклоняется. Перекидывать на другой аккаунт можно только когда
  заполнен дневной/месячный оборот мерчант-аккаунта.
- **Каждая операция — в журнале (ledger)** с привязкой к игроку, оператору, провайдеру и аккаунту.
- **Идемпотентность:** повторный запрос с тем же ключом не создаёт второй платёж.
- **Секреты не хранятся в репозитории.** Ключи провайдеров — только в переменных окружения.
- **Изменения — через pull request**, в `main` ничего не попадает без ревью.

## Защита кода

- `main` защищён: только через pull request с зелёным CI и одобрением владельца (CODEOWNERS).
- Зависимости: точные версии в `package-lock.json`, установочные скрипты пакетов запрещены (`.npmrc`),
  `npm audit` в CI, еженедельные обновления от Dependabot.
- GitHub Actions закреплены по хэшу коммита, у CI права только на чтение.
- Код проприетарный, см. `LICENSE`.

## Структура

| Папка | Что внутри |
|---|---|
| `prototype/` | Интерактивный прототип роутера на мок-аккаунтах (открыть `router.html` в браузере) |
| `src/` | Сервер: Node.js + TypeScript + Fastify |
| `migrations/` | SQL-схема базы (PostgreSQL), применяется по порядку |
| `test/` | Автотесты (vitest) |

## Запуск локально

Нужны Node.js 20+ и Docker.

```bash
cp .env.example .env
docker compose up -d          # PostgreSQL
npm install
npm run migrate               # создать таблицы
npm run dev                   # сервер на http://localhost:3000
```

Проверка: `GET /health` — процесс жив, `GET /ready` — есть связь с базой.

Тесты: `npm test`. Тесты базы запускаются, если задан `TEST_DATABASE_URL`
(в GitHub Actions задаётся автоматически).

## Модель данных

- **operators** — владелец лицензии; **sites** — его сайты, которые ходят в API (храним только хэш ключа).
- **providers** — тип интеграции; **merchant_accounts** — конкретные аккаунты с валютами, странами,
  мин/макс суммой, дневным/месячным лимитом, порогом переключения (95%) и комиссией.
- **account_usage** — оборот аккаунта по дням; строка блокируется при резервировании лимита.
- **players** — игрок сайта: страна, KYC, свой лимит депозитов, самоисключение, «липкий» аккаунт.
- **transactions** / **transaction_attempts** — платёж и каждая попытка через конкретный аккаунт (каскад).
- **ledger_entries** — журнал проводок, только добавление (изменение и удаление запрещены на уровне базы).

Суммы — `BIGINT` в минорных единицах (центы), никаких дробных чисел для денег.
